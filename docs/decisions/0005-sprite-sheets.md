# ADR 0005：以声明式 sprite sheet 交付立绘

- 日期：2026-11-05
- 状态：已采用（待所有者确认画布/头部基准）

## 背景

所有者把全部立绘与背景的 SVG 版本放进了 `assets/_inbox/`。立绘是 9 张 sprite sheet：
每张 `viewBox="0 0 1600 1200"`，由 4×2 个 `translate(...)` 网格单元组成，单元为
400×600；每个单元用 `clipPath` 裁到 400×540，并在底部用 `<text>` 标注角色名
（学生表）或 `1. neutral … 8. embarrassed`（主角表）。背景是 3 张
`viewBox="0 0 1920 1080"` 的完整 SVG。

`AGENTS.md` 8.6 原本只接受逐张命名文件（`<中文名>_<表情>.svg`），并要求画布
400×520 单位 / 800×1040 像素，同时禁止导入工具「猜测」拆图。

## 选项

1. 请所有者把每张 sheet 手工拆成 69 个文件后重新交付。
2. 由导入工具读取 sheet **自带的**网格、裁切框与标签，确定性地拆图。
3. 不拆图，继续用程序占位立绘。

## 决定

选 2。新增 `tools/extract-sheets.ts`：

- 只接受声明了 `1600×1200`、单元 `400×600`、裁切框 `400×540` 的 sheet；结构与标注
  不符就报错，不按像素或经验推断。
- 以每格的 `<text>` 为身份来源：`N. <expression>` 归属文件名对应的主角；
  中文名归属 `data/characters.yaml` 里的学生（表情固定 `neutral`）。
- 丢掉格子底色矩形、边框和标签文字，只保留 `clip-path="url(#clip)"` 内的画稿，
  输出透明背景的 `400×540` SVG 到 `assets/_inbox/derived/`，再由现有
  `tools/ingest-art.ts` 校验、转码并写入清单。
- 输出画布统一为 **800×1080**（400×540 @2x），不再使用 800×1040。所有角色、所有
  表情完全相同，仍然 never-trim。

运行方式：`pnpm ingest:art`（先拆分，再导入）。

## 后果

- `assets/manifest.yaml` 的 `size` 为 `[800, 1080]`；`check:assets` 已同步。
- `AGENTS.md` 8.2 的 400×520 / 800×1040 数字按本 ADR 调整为 400×540 / 800×1080。
  头部基准也随之调整：实际出图中头部中心约在 (200, 190) 单位、眼线约 y=198；
  原先的 (400, 340) px / 眼线 356 px 对应旧素材，不再适用。
- 舞台显示比例改为单人 0.79、2–3 人 0.62，并把立绘底边放在 y=860，使脸部落在
  画面上三分之一、腰部平切被对话框遮住。比例可用 `characters.yaml` 的
  `stage_scale` 微调。
- 拆分结果是 `assets/_src/<CharacterId>_<表情>.svg`（入库），中间文件
  `assets/_inbox/` 仍然 gitignore。
- 新增素材若不符合该声明式结构，导入会失败并列出问题，而不是静默切图。
